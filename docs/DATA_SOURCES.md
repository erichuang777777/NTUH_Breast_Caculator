# Data Sources

## 原則

- 資料來源必須能對應到具體腳本或人工維護流程
- 若來源目前未完全自動化，要明寫「人工確認」
- 每次更新最好留日期與來源版本

## 1. 健保藥價 / 健保規定

### 目前 repo 內已實作

- `update_official_prices.py`
- 來源：`115年藥品支付價格年度例行調整結果明細表`
- 用途：將公告藥價寫入 `drugs.nhi_price` 與 `price_unit`

說明：

- 目前這支腳本是以人工整理好的常數表更新資料庫
- 屬於「公告結果匯入」，不是即時對接官方 API

### 健保 Open Data API

目前狀態：

- 本 repo 目前沒有正式接上健保 Open Data API 的自動同步腳本
- 若後續要補，建議在文件與程式中明確標示 API 名稱、欄位對應與更新日期

建議記錄項目：

- API 名稱
- 更新日期
- 對應到資料庫哪些欄位
- 是否需要人工覆核

### 單藥 PDF

目前狀態：

- repo 內沒有完整的單藥 PDF 自動抓取或解析流程
- 單藥 PDF 應視為人工覆核來源，不要假裝是已全自動化來源

建議用途：

- 核對單一藥物給付文字
- 確認治療線、事前審查條件
- 當 API / 公告表與臨床使用情境不一致時作為人工裁決依據

## 2. 台大醫院來源

### 台大價目表匯入

- `import_ntuh_prices.py`
- 來源：`2024_12_5_price.csv`
- 用途：重建 `drug_formulations`，並保留 NTUH 價格欄位

特性：

- 偏向批次匯入
- 適合重新建立規格、院內價格、劑型資料

### 台大即時查價

- `update_ntuh_prices.py`
- 來源：台大藥劑部查價頁 `https://dept.ntuh.gov.tw/phar/WebAp/QueryDrugInfoPhr.aspx`
- 用途：更新 `ntuh_drug_codes` 與 `price_history`

特性：

- 可補查院內代碼
- 可記錄查詢時間與價格異動
- 比較接近維護用同步資料，不等同正式版本主檔

## 3. 臨床試驗來源

- `clinical_trials_lib/clinical_trials_core.py`
- 來源：ClinicalTrials.gov API v2
- 用途：Flask 臨床試驗模組使用

說明：

- 這部分不是主藥物查詢站的核心資料來源
- 若靜態站部署，不應依賴這個來源才能使用主功能

## 4. 可重建與應進版控

### 建議可重建、不新增進版控

- 重新 build 後的輸出頁
- 測試 cache
- 臨時查詢輸出
- 中間轉換檔

### 建議保留在版控

- 原始維護腳本
- 不易重建的對照表
- specialty 模組包裝層
- 維護必要文件

## 5. 維護要求

每次資料更新至少要能回答：

- 這筆資料來自哪個來源
- 來源日期是什麼
- 是自動更新還是人工確認
- 是否已重建靜態頁
